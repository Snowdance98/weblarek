# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

## Документация слоя Представления (View)

Документ описывает **классы слоя View**, необходимые для отображения интерфейса интернет‑магазина «Web‑Larёk» по разметке и шаблонам из `index.html`.

## Общие принципы View-слоя

- **Один класс = один “блок” разметки**. Компонент отвечает только за свой DOM‑контейнер и его вложенные элементы.
- **View не содержит бизнес‑логики**: не решает “можно ли купить”, “валиден ли заказ” и т.д. Он только:
  - отображает входные данные (из презентера),
  - собирает пользовательский ввод,
  - генерирует события.
- **Любое действие пользователя порождает событие**, которое будет обработано презентером (через `EventEmitter`).
- Все компоненты View должны быть построены на базовом `Component<T>` (`src/components/base/Component.ts`).

## Базовые зависимости и контракт

### `Component<T>` (база для всех View)

Базовый класс уже есть в проекте: `src/components/base/Component.ts`.

- **Зона ответственности**: хранит `container` и предоставляет `render(data?: Partial<T>)`.
- **Механика**: `render` делает `Object.assign(this, data)` → в дочерних классах ожидаются **сеттеры**, которые обновляют DOM.

### `IEvents` / `EventEmitter`

Брокер событий уже есть в проекте: `src/components/base/Events.ts`.

- View‑компоненты получают `events: IEvents` и вызывают `events.emit(...)` при пользовательских действиях.

## Классы View (обязательные для отображения сайта)

Ниже перечислены компоненты, которые покрывают весь UI из макета/вёрстки.
Названия классов можно адаптировать под стиль проекта, но **структура наследования и ответственность должны сохраниться**.

### 1) `Page` (корневой view-компонент страницы)

- **Контейнер**: `document.body` или `.page`
- **Зона ответственности**:
  - установка/снятие “блокировки” страницы при открытой модалке (например, класс для scroll‑lock),
  - делегирование “глобальных” состояний: активная модалка, затемнение, etc.
- **Входные данные (пример)**:
  - `locked: boolean` — запрещена ли прокрутка
- **События**:
  - обычно не эмитит сам по себе, но может эмитить “глобальные” события (например, `page:escape` при нажатии Esc, если вы реализуете это на уровне страницы).

### 2) `Header` (шапка сайта)

- **Контейнер**: `.header`
- **DOM**:
  - `.header__basket` (кнопка корзины)
  - `.header__basket-counter` (счётчик)
- **Зона ответственности**:
  - отображение количества товаров в корзине,
  - генерация события по клику на корзину.
- **Входные данные (пример)**:
  - `counter: number`
- **События**:
  - `basket:open` — пользователь нажал на кнопку корзины.

### 3) `Gallery` (каталог товаров)

- **Контейнер**: `main.gallery`
- **Зона ответственности**:
  - рендер списка карточек каталога (используя `CardCatalog`),
  - не знает ничего про корзину/заказ — только отображает список и эмитит “выбор карточки”.
- **Входные данные (пример)**:
  - `items: HTMLElement[]` (готовые DOM карточек) или `items: IProduct[]` (если галерея сама создаёт карточки)
- **События**:
  - напрямую обычно не эмитит (эмитят карточки), но допускается `gallery:item-select` если вы делаете делегирование кликов на уровне галереи.

## Карточки (3 шаблона, один родитель)

Требование: **три класса карточек работают с разными шаблонами, но имеют одного родителя**.

### 4) `CardBase` (родитель для карточек)

- **Контейнер**: корневой элемент карточки из `<template>`
- **Общее для всех карточек** (выносится сюда):
  - получение ссылок на общие DOM‑элементы (`.card__title`, `.card__price`, `.card__image`, `.card__category` — если есть),
  - сеттеры общих полей: `title`, `price`, `image`, `category`,
  - вспомогательные методы форматирования цены/категории,
  - базовый `render`.
- **Входные данные (пример)**:
  - `id: string`
  - `title: string`
  - `price: number | null`
  - `image?: string`
  - `category?: string`
- **События**:
  - базовый класс не обязан эмитить, но может содержать общую утилиту `emit(eventName, payload)`.

### 5) `CardCatalog` (карточка в каталоге)

- **Шаблон**: `template#card-catalog`
- **Контейнер**: `button.gallery__item.card`
- **Зона ответственности**:
  - отображение кратких данных товара,
  - событие выбора карточки (открытие превью).
- **События**:
  - `card:select` (payload: `{ id }`) — клик по карточке в каталоге.

### 6) `CardPreview` (карточка‑превью товара)

- **Шаблон**: `template#card-preview`
- **Контейнер**: `.card.card_full`
- **DOM**:
  - `.card__text` (описание)
  - `.card__button` (кнопка “В корзину”)
- **Зона ответственности**:
  - отображение подробных данных товара,
  - отображение состояния кнопки (“В корзину” / “Уже в корзине” / disabled при `price === null` — если такое предусмотрено презентером),
  - генерация события добавления в корзину.
- **События**:
  - `card:add-to-basket` (payload: `{ id }`) — клик по кнопке “В корзину”.

### 7) `CardBasket` (позиция в корзине)

- **Шаблон**: `template#card-basket`
- **Контейнер**: `li.basket__item.card_compact`
- **DOM**:
  - `.basket__item-index`
  - `.basket__item-delete`
- **Зона ответственности**:
  - отображение позиции товара в списке корзины,
  - событие удаления товара.
- **События**:
  - `basket:remove` (payload: `{ id }`) — клик по кнопке удаления.

## Модальное окно (без наследников)

Требование: **модальное окно не может иметь дочерних классов**.

### 8) `Modal`

- **Контейнер**: `#modal-container`
- **DOM**:
  - `.modal__close`
  - `.modal__content`
- **Зона ответственности**:
  - показать/скрыть модалку,

- **Методы (ожидаемые)**:
  - `open(content: HTMLElement): void`
  - `close(): void`
  - `render(...)` при необходимости
- **События**:

  - `modal:close`

## Презентер

В приложении одна страница, поэтому используется **один презентер**.

- **Выбранный подход**: презентер реализован **в `src/main.ts`** (без отдельного класса).
- **Зона ответственности**:
  - подписка на события от View и Model через `EventEmitter`;
  - вызовы методов моделей для изменения данных;
  - открытие модального окна и передача в него готовых компонентов;
  - перерисовка View **только**:
    - при обработке событий от моделей (данные изменились),
    - или при обработке события открытия модального окна (когда нужно показать новый контент).
- **Важно**: презентер **не генерирует события** (`emit` не используется в презентере), он только обрабатывает их.

## Примечания по реализации (чтобы соответствовать требованиям)

- **Modal не наследуется**: `Modal` — финальный компонент, контент внутри — это `BasketView`, `OrderForm`, `ContactsForm`, `SuccessView` и т.п.
- **Карточки**: `CardCatalog`, `CardPreview`, `CardBasket` обязаны наследоваться от `CardBase`.
- **Формы**: `OrderForm` и `ContactsForm` обязаны наследоваться от `FormBase`.
- **Композиция**: `Gallery` хранит/рендерит много `CardCatalog`; `BasketView` хранит/рендерит много `CardBasket`; `Modal` отображает любой компонент через `open(content)`.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

#### Класс Product
Класс отвечает за хранение и управление данными каталога товаров. Хранит список всех доступных товаров и выбранный для детального просмотра товар.

Конструктор класса не принимает параметров, инициализирует пустые структуры данных.

Поля класса:
`_items: IProduct[]` - массив всех товаров каталога

Методы класса:

`setSelectedItem(item: IProduct | null): void` - сохраняет товар для детального отображения
`getSelectedItem(): IProduct | null` - возвращает товар для детального отображения

#### Класс Cart
Класс отвечает за хранение и управление товарами в корзине покупателя. Реализует логику добавления, удаления и расчета стоимости товаров.

Конструктор класса не принимает параметров, инициализирует пустую корзину.

Поля класса:
`_items: IProduct[]` - массив товаров в корзине

Методы класса:
`getItems(): IProduct[]` - возвращает массив товаров в корзине
`addItem(item: IProduct): void` - добавляет товар в корзину
`removeItem(item: IProduct): void` - удаляет товар из корзины
`clear(): void` - очищает корзину
`getTotalPrice(): number` - возвращает общую стоимость всех товаров в корзине
`getItemsCount(): number` - возвращает количество товаров в корзине
`isInCart(id: string): boolean` - проверяет наличие товара в корзине по его id

#### Класс Order
Класс отвечает за хранение, валидацию и управление данными покупателя при оформлении заказа.

Конструктор класса не принимает параметров, инициализирует пустые поля данных.

Поля класса:
`_payment: TPayment` - способ оплаты
`_email: string` - электронная почта
`_phone: string` - телефон
`_address: string` - адрес

Методы класса:
`setData(data: Partial<IBuyer>): void` - сохраняет данные покупателя (можно сохранять как все поля сразу, так и отдельно)
`getData(): IBuyer` - возвращает все данные покупателя
`clear(): void` - очищает все данные покупателя
`validate(): IValidationResult` - проверяет валидность всех полей и возвращает объект с ошибками
