# Документация слоя Представления (View)

Документ описывает **классы слоя View**, необходимые для отображения интерфейса интернет‑магазина «Web‑Larёk» по разметке и шаблонам из `index.html`.

## Общие принципы View-слоя

- **Один класс = один “блок” разметки**. Компонент отвечает только за свой DOM‑контейнер и его вложенные элементы.
- **View не содержит бизнес‑логики**: не решает “можно ли купить”, “валиден ли заказ” и т.д. Он только:
  - отображает входные данные (из презентера),
  - собирает пользовательский ввод,
  - генерирует события.
- **Любое действие пользователя порождает событие**, которое будет обработано презентером (через `EventEmitter`).
- Все компоненты View должны быть построены на базовом `Component<T>` (`src/components/base/Component.ts`).

## Базовые зависимости и контракт

### `Component<T>` (база для всех View)

Базовый класс уже есть в проекте: `src/components/base/Component.ts`.

- **Зона ответственности**: хранит `container` и предоставляет `render(data?: Partial<T>)`.
- **Механика**: `render` делает `Object.assign(this, data)` → в дочерних классах ожидаются **сеттеры**, которые обновляют DOM.

### `IEvents` / `EventEmitter`

Брокер событий уже есть в проекте: `src/components/base/Events.ts`.

- View‑компоненты получают `events: IEvents` и вызывают `events.emit(...)` при пользовательских действиях.

## Классы View (обязательные для отображения сайта)

Ниже перечислены компоненты, которые покрывают весь UI из макета/вёрстки.
Названия классов можно адаптировать под стиль проекта, но **структура наследования и ответственность должны сохраниться**.

### 1) `Page` (корневой view-компонент страницы)

- **Контейнер**: `document.body` или `.page`
- **Зона ответственности**:
  - установка/снятие “блокировки” страницы при открытой модалке (например, класс для scroll‑lock),
  - делегирование “глобальных” состояний: активная модалка, затемнение, etc.
- **Входные данные (пример)**:
  - `locked: boolean` — запрещена ли прокрутка
- **События**:
  - обычно не эмитит сам по себе, но может эмитить “глобальные” события (например, `page:escape` при нажатии Esc, если вы реализуете это на уровне страницы).

### 2) `Header` (шапка сайта)

- **Контейнер**: `.header`
- **DOM**:
  - `.header__basket` (кнопка корзины)
  - `.header__basket-counter` (счётчик)
- **Зона ответственности**:
  - отображение количества товаров в корзине,
  - генерация события по клику на корзину.
- **Входные данные (пример)**:
  - `counter: number`
- **События**:
  - `basket:open` — пользователь нажал на кнопку корзины.

### 3) `Gallery` (каталог товаров)

- **Контейнер**: `main.gallery`
- **Зона ответственности**:
  - рендер списка карточек каталога (используя `CardCatalog`),
  - не знает ничего про корзину/заказ — только отображает список и эмитит “выбор карточки”.
- **Входные данные (пример)**:
  - `items: HTMLElement[]` (готовые DOM карточек) или `items: IProduct[]` (если галерея сама создаёт карточки)
- **События**:
  - напрямую обычно не эмитит (эмитят карточки), но допускается `gallery:item-select` если вы делаете делегирование кликов на уровне галереи.

## Карточки (3 шаблона, один родитель)

Требование: **три класса карточек работают с разными шаблонами, но имеют одного родителя**.

### 4) `CardBase` (родитель для карточек)

- **Контейнер**: корневой элемент карточки из `<template>`
- **Общее для всех карточек** (выносится сюда):
  - получение ссылок на общие DOM‑элементы (`.card__title`, `.card__price`, `.card__image`, `.card__category` — если есть),
  - сеттеры общих полей: `title`, `price`, `image`, `category`,
  - вспомогательные методы форматирования цены/категории,
  - базовый `render`.
- **Входные данные (пример)**:
  - `id: string`
  - `title: string`
  - `price: number | null`
  - `image?: string`
  - `category?: string`
- **События**:
  - базовый класс не обязан эмитить, но может содержать общую утилиту `emit(eventName, payload)`.

### 5) `CardCatalog` (карточка в каталоге)

- **Шаблон**: `template#card-catalog`
- **Контейнер**: `button.gallery__item.card`
- **Зона ответственности**:
  - отображение кратких данных товара,
  - событие выбора карточки (открытие превью).
- **События**:
  - `card:select` (payload: `{ id }`) — клик по карточке в каталоге.

### 6) `CardPreview` (карточка‑превью товара)

- **Шаблон**: `template#card-preview`
- **Контейнер**: `.card.card_full`
- **DOM**:
  - `.card__text` (описание)
  - `.card__button` (кнопка “В корзину”)
- **Зона ответственности**:
  - отображение подробных данных товара,
  - отображение состояния кнопки (“В корзину” / “Уже в корзине” / disabled при `price === null` — если такое предусмотрено презентером),
  - генерация события добавления в корзину.
- **События**:
  - `card:add-to-basket` (payload: `{ id }`) — клик по кнопке “В корзину”.

### 7) `CardBasket` (позиция в корзине)

- **Шаблон**: `template#card-basket`
- **Контейнер**: `li.basket__item.card_compact`
- **DOM**:
  - `.basket__item-index`
  - `.basket__item-delete`
- **Зона ответственности**:
  - отображение позиции товара в списке корзины,
  - событие удаления товара.
- **События**:
  - `basket:remove` (payload: `{ id }`) — клик по кнопке удаления.

## Модальное окно (без наследников)

Требование: **модальное окно не может иметь дочерних классов**.

### 8) `Modal`

- **Контейнер**: `#modal-container`
- **DOM**:
  - `.modal__close`
  - `.modal__content`
- **Зона ответственности**:
  - показать/скрыть модалку,
  - вставить произвольный контент внутрь `.modal__content`,
  - закрытие по клику на крестик/оверлей (если реализовано) / Esc (если реализовано),
  - не знает, *что* находится внутри (корзина, формы, успех — это отдельные компоненты).
- **Методы (ожидаемые)**:
  - `open(content: HTMLElement): void`
  - `close(): void`
  - `render(...)` при необходимости
- **События**:
  - `modal:open`
  - `modal:close`

## Контент модалки (самостоятельные компоненты)

### 9) `BasketView` (экран корзины)

- **Шаблон**: `template#basket`
- **Контейнер**: `.basket`
- **DOM**:
  - `.basket__list` (список позиций)
  - `.basket__price` (итого)
  - `.basket__button` (кнопка “Оформить”)
- **Зона ответственности**:
  - рендер списка `CardBasket`,
  - показ общей суммы,
  - генерация события “перейти к оформлению”.
- **Входные данные (пример)**:
  - `items: HTMLElement[]`
  - `total: number`
  - `canSubmit: boolean` (например, если корзина пуста)
- **События**:
  - `basket:submit` — клик “Оформить”.

## Формы (2 шаблона, один родитель)

Требование: **две формы имеют общего родителя**, в который вынесен общий функционал.

### 10) `FormBase` (родитель форм)

- **Контейнер**: `form.form`
- **Общее для всех форм** (выносится сюда):
  - подписка на `input`/`change` и сбор значений,
  - управление кнопкой submit (`disabled/enabled`),
  - вывод ошибок в `.form__errors`,
  - событие “изменилось значение поля”,
  - событие “форма отправлена”.
- **Входные данные (пример)**:
  - `valid: boolean`
  - `errors: string` (или массив/словарь ошибок, который презентер превратит в строку)
- **События**:
  - `form:change` (payload: `{ field, value, form }`)
  - `form:submit` (payload: `{ form }`)

### 11) `OrderForm` (шаг 1: оплата и адрес)

- **Шаблон**: `template#order`
- **Контейнер**: `form[name="order"]`
- **DOM**:
  - кнопки оплаты `.order__buttons button[name="card"|"cash"]` (type="button")
  - `input[name="address"]`
  - submit `.order__button`
- **Зона ответственности**:
  - отображение выбранного способа оплаты (активная кнопка),
  - передача изменения адреса/оплаты в презентер через события,
  - submit переходит к шагу контактов (решает презентер).
- **События**:
  - `order:payment-select` (payload: `{ payment: 'online' | 'cash' }` или ваш тип)
  - `order:address-change` (payload: `{ address }`)
  - `order:submit`

### 12) `ContactsForm` (шаг 2: email и телефон)

- **Шаблон**: `template#contacts`
- **Контейнер**: `form[name="contacts"]`
- **DOM**:
  - `input[name="email"]`
  - `input[name="phone"]`
  - submit (кнопка “Оплатить”)
- **Зона ответственности**:
  - передача изменения email/телефона,
  - submit инициирует отправку заказа (решает презентер).
- **События**:
  - `contacts:email-change` (payload: `{ email }`)
  - `contacts:phone-change` (payload: `{ phone }`)
  - `contacts:submit`

### 13) `SuccessView` (экран успеха)

- **Шаблон**: `template#success`
- **Контейнер**: `.order-success`
- **DOM**:
  - `.order-success__description` (текст “Списано N синапсов”)
  - `.order-success__close` (кнопка “За новыми покупками!”)
- **Зона ответственности**:
  - показать итоговую сумму списания,
  - дать пользователю закрыть модалку и вернуться к каталогу.
- **Входные данные (пример)**:
  - `total: number`
- **События**:
  - `success:close`

## Рекомендуемая схема событий (сводка)

Ниже — минимальный набор, который покрывает весь UI. Можно назвать иначе, но важно: **событие должно генерироваться на каждое действие пользователя**.

- `basket:open` — открыть корзину (Header)
- `card:select` — открыть превью товара (CardCatalog)
- `card:add-to-basket` — добавить товар в корзину (CardPreview)
- `basket:remove` — удалить товар (CardBasket)
- `basket:submit` — перейти к оформлению (BasketView)
- `order:payment-select`, `order:address-change`, `order:submit` — шаг “order”
- `contacts:email-change`, `contacts:phone-change`, `contacts:submit` — шаг “contacts”
- `success:close` — закрыть успех
- `modal:open`, `modal:close` — состояние модального окна

## События приложения (реально генерируются View-классами)

Этот раздел нужно поддерживать актуальным: **добавляйте сюда событие каждый раз, когда вы делаете `events.emit(...)`** в любом компоненте View.

### Глобальные события UI

- **`modal:open`**: модальное окно открыто (`Modal.open()`).
- **`modal:close`**: модальное окно закрыто (`Modal.close()` по крестику, оверлею или Esc).

### Каталог / карточки

- **`card:select`**: пользователь кликнул по карточке в каталоге, нужно открыть превью. Payload: `{ id: string }`.
- **`card:add-to-basket`**: пользователь нажал “В корзину” в превью. Payload: `{ id: string }`.

### Корзина

- **`basket:open`**: пользователь нажал на иконку корзины в шапке.
- **`basket:remove`**: пользователь удалил товар из корзины. Payload: `{ id: string }`.
- **`basket:submit`**: пользователь нажал “Оформить” в корзине.

### Формы

- **`form:change`**: изменилось значение любого поля формы. Payload: `{ form: string, field: string, value: string }`.
- **`form:submit`**: базовое событие submit формы. Payload: `{ form: string }`.
- **`order:payment-select`**: выбран способ оплаты. Payload: `{ payment: 'online' | 'upon receipt' }`.
- **`order:address-change`**: изменился адрес доставки. Payload: `{ address: string }`.
- **`order:submit`**: отправлен шаг “order”.
- **`contacts:email-change`**: изменился email. Payload: `{ email: string }`.
- **`contacts:phone-change`**: изменился телефон. Payload: `{ phone: string }`.
- **`contacts:submit`**: отправлен шаг “contacts”.

### Успешный заказ

- **`success:close`**: пользователь закрыл экран успеха.

## События моделей данных (реально генерируются Model-классами)

Этот раздел нужно поддерживать актуальным: **добавляйте сюда событие каждый раз, когда вы делаете `events.emit(...)`** в любой модели данных.

### `Products`

- **`products:items-changed`**: обновлён список товаров в модели. Payload: `{ items: IProduct[] }`.
- **`products:selected-changed`**: изменён выбранный товар (для превью). Payload: `{ item: IProduct | null }`.

### `Cart`

- **`cart:changed`**: изменилось содержимое корзины. Payload: `{ items: IProduct[], action: 'add' | 'remove' | 'clear', item?: IProduct }`.

### `Order`

- **`order:changed`**: изменились данные заказа (частично). Payload: `Partial<IBuyer>`.
- **`order:cleared`**: данные заказа очищены.

## Презентер

В приложении одна страница, поэтому используется **один презентер**.

- **Выбранный подход**: презентер реализован **в `src/main.ts`** (без отдельного класса).
- **Зона ответственности**:
  - подписка на события от View и Model через `EventEmitter`;
  - вызовы методов моделей для изменения данных;
  - открытие модального окна и передача в него готовых компонентов;
  - перерисовка View **только**:
    - при обработке событий от моделей (данные изменились),
    - или при обработке события открытия модального окна (когда нужно показать новый контент).
- **Важно**: презентер **не генерирует события** (`emit` не используется в презентере), он только обрабатывает их.

## Примечания по реализации (чтобы соответствовать требованиям)

- **Modal не наследуется**: `Modal` — финальный компонент, контент внутри — это `BasketView`, `OrderForm`, `ContactsForm`, `SuccessView` и т.п.
- **Карточки**: `CardCatalog`, `CardPreview`, `CardBasket` обязаны наследоваться от `CardBase`.
- **Формы**: `OrderForm` и `ContactsForm` обязаны наследоваться от `FormBase`.
- **Композиция**: `Gallery` хранит/рендерит много `CardCatalog`; `BasketView` хранит/рендерит много `CardBasket`; `Modal` отображает любой компонент через `open(content)`.
